# Memory Hygiene Checklist

- [ ] Does `.engineering/` contain only durable engineering context (not temporary scratch)?
- [ ] Are all secrets, tokens, passwords, and private certificates completely excluded?
- [ ] Are ADRs numbered sequentially with context, alternatives, and consequences?
- [ ] Are bug lessons captured with explicit forward-looking invariants?
- [ ] Is `.engineering/` committed to Git alongside source code changes?
